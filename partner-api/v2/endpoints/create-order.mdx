---
title: "Create an order"
api: "POST /api/partner/v2/orders"
description: "Buy 1-10 packs of one kind for one wallet, paid with one payment, or for one customer on a non-crypto program."
---

Scope: `nft:orders` · Rate limit: 30 a minute, shared with [Sell back a customer's card](/partner-api/v2/endpoints/sell-back-customer-card) and [Create a customer shipment](/partner-api/v2/endpoints/create-customer-shipment)

One order buys 1-10 packs of one kind for one wallet, paid with one payment. The response has the order and how to pay it ([Payments](/partner-api/v2/payments)). The pack opens and the NFT mints once the payment settles. Follow it with [Get an order](/partner-api/v2/endpoints/get-order) or the `nft_order.updated` [webhook](/partner-api/v2/webhooks).

A refused order creates nothing. There is no limit on how much a wallet buys.

<Note>
  **non-crypto programs** ([Non-crypto model](/partner-api/v2/settlement)): send `customer`, your own id for the customer, and no wallet fields. There is no payment step: the order is charged to your statement when it is accepted, its packs open at once, and the response has no `payment`. The order has `custody: "vault"` and `customer`, `recipient` and `mint_chain` are null, and each pack ends `in_vault` instead of `minted` (or `refunded`, with the price taken back off your statement, if it can't open). The first order for a new `customer` creates that customer. Your credit limit and daily limits apply.
</Note>

<Warning>
  Always send an `Idempotency-Key`, and reuse it when retrying the same order. See [Idempotency](/partner-api/v2/idempotency).
</Warning>

<ParamField header="Idempotency-Key" type="string" required>
  Your own order id: 8-128 characters of `A-Za-z0-9_-`, one per order. It becomes the order's `order_id`.
</ParamField>
<ParamField body="pack_type" type="string" required>
  A `pack_type` from [List packs](/partner-api/v2/endpoints/list-packs).
</ParamField>
<ParamField body="category" type="string" default="pokemon">
  As for [List packs](/partner-api/v2/endpoints/list-packs).
</ParamField>
<ParamField body="odds" type="string">
  `standard`, `hot`, `chill` or `classic`: one the pack sells. Default: the pack's `default_odds`. See [Odds](/partner-api/v2/odds).
</ParamField>
<ParamField body="quantity" type="integer" default="1">
  1-10 packs. 2 or more makes a [multi-pack order](/partner-api/v2/orders#multi-pack-orders).
</ParamField>
<ParamField body="recipient" type="string">
  **Crypto Wallet model only, and required there.** The customer's self-custody wallet on your mint chain. Never an exchange deposit address: the NFTs are minted to it.
</ParamField>
<ParamField body="refund_address" type="string">
  Crypto Wallet model only. An EVM wallet that can receive USDC on Base, for refunds. Defaults to `recipient` on an EVM program. **Required when you mint on Solana.**
</ParamField>
<ParamField body="partner_user_ref" type="string">
  Crypto Wallet model: your opaque user id (`A-Z a-z 0-9 _ . : -`, up to 128). Never put personal data here. Not used on a non-crypto program, where `customer` names the customer.
</ParamField>
<ParamField body="customer" type="string">
  **non-crypto programs only, and required there.** Your own id for the customer: 1-128 characters of `A-Z a-z 0-9 _ . : -`. Use something stable that is not personal data (your internal user id, never an email address or phone number). The same `Idempotency-Key` with a different `customer` is `422`.
</ParamField>

## Response

**201** (200 with `"idempotent_replay": true` on a replay).

<ResponseField name="order" type="object">
  The order, as [Get an order](/partner-api/v2/endpoints/get-order) returns it. A multi-pack order has `quantity`, `unit_price`, `price` (the total) and `units`.
  <Expandable title="order">
    <ResponseField name="order_id" type="string">Your `Idempotency-Key`.</ResponseField>
    <ResponseField name="id" type="string">Our id. Either works in `GET /orders/{id}`.</ResponseField>
    <ResponseField name="status" type="string">`awaiting_payment`; on a non-crypto program, `in_vault` once the pack has opened. See [Orders and statuses](/partner-api/v2/orders).</ResponseField>
    <ResponseField name="pack_type" type="string" />
    <ResponseField name="category" type="string" />
    <ResponseField name="odds" type="string">The odds the pack is opened at.</ResponseField>
    <ResponseField name="price" type="number">The amount due, in dollars.</ResponseField>
    <ResponseField name="recipient" type="string | null">Null on a non-crypto program.</ResponseField>
    <ResponseField name="mint_chain" type="string | null">Null on a non-crypto program.</ResponseField>
    <ResponseField name="paid_at" type="string | null" />
    <ResponseField name="custody" type="string">`wallet` (the item mints as an NFT to `recipient`) or `vault` (Non-crypto model: the card stays in the `customer`'s CatchBack vault). On a multi-pack order, on each unit.</ResponseField>
    <ResponseField name="customer" type="string">Only when `custody` is `vault`: the customer, by your own id.</ResponseField>
    <ResponseField name="pull" type="object | null">Null until the pack opens.</ResponseField>
    <ResponseField name="token" type="object | null">Null until the NFT is minted.</ResponseField>
    <ResponseField name="failure_reason" type="string | null" />
    <ResponseField name="created_at" type="string" />
  </Expandable>
</ResponseField>
<ResponseField name="payment" type="object">
  Crypto Wallet model only: a non-crypto order has no `payment`. `intent_id`, `client_secret`, `publishable_key`, `amount` and `deposit_addresses`. See [Payments](/partner-api/v2/payments). Once the order is past `awaiting_payment`, a replay's `payment` has no `client_secret` and no deposit addresses: there is nothing left to pay.
</ResponseField>
<ResponseField name="idempotent_replay" type="boolean">Present and `true` on a replay.</ResponseField>

If the chosen odds stop selling before the payment settles, the pack isn't opened at other odds: the order goes to `refund_due` and the customer is refunded.

## Errors

| Status | Code | When |
|---|---|---|
| `400` | `BAD_IDEMPOTENCY_KEY` | `Idempotency-Key` missing or malformed |
| `400` | `BAD_JSON` | The body isn't JSON |
| `400` | `BAD_RECIPIENT` | `recipient` is not a wallet address on your mint chain |
| `400` | `BAD_PACK` | `pack_type` missing |
| `400` | `BAD_CATEGORY` | Unknown `category` |
| `400` | `BAD_ODDS` | `odds` isn't a known choice, or the pack doesn't sell it (`odds` lists the choices) |
| `400` | `BAD_QUANTITY` | `quantity` isn't a whole number from 1 to 10 |
| `400` | `BAD_REFUND_ADDRESS` | No usable EVM `refund_address` (required when you mint on Solana) |
| `400` | `WALLET_FIELDS_NOT_ACCEPTED` | Non-crypto model: `recipient` or `refund_address` was sent. Send `customer` only |
| `400` | `BAD_CUSTOMER` | Non-crypto model: `customer` is missing, or not 1-128 characters of `A-Z a-z 0-9 _ . : -` |
| `402` | `CREDIT_LIMIT` | Non-crypto model: the order would take what you owe past your credit limit. The body has `owed`, `credit_limit` and `order_total`. Nothing is charged |
| `403` | `WALLET_REFUSED` | A wallet in the request failed sanctions screening |
| `403` | `WALLET_BLOCKED` | This wallet may not buy from CatchBack |
| `403` | `CUSTOMER_BLOCKED` | Non-crypto model: we can't sell to this customer. Don't retry |
| `404` | `PACK_NOT_OFFERED` | That pack isn't sold through your program |
| `409` | `ODDS_UNAVAILABLE` | Those odds aren't selling right now. Nothing is created |
| `409` | `PACK_UNAVAILABLE` | A pack that sells only its own odds can't open right now; `reason` says why. Nothing is created |
| `422` | `IDEMPOTENCY_KEY_REUSED` | The key was already used for a different order |
| `429` | `CUSTOMER_DAILY_LIMIT` | Non-crypto model: this customer has spent their limit for the UTC day. The body has `spent_today`, `limit`, `order_total` and `retry_after_seconds` |
| `429` | `DAILY_LIMIT` | Non-crypto model: your program has spent its daily limit, if it has one. Same fields |
| `503` | `SCREENING_UNAVAILABLE` | Wallet screening is briefly unavailable; retry shortly |
| `503` | `CUSTOMER_CHECK_UNAVAILABLE` | Non-crypto model: we couldn't check the customer just now. Nothing is charged; retry shortly with the same key |

<RequestExample>
```bash cURL
curl -X POST https://catchbackcards.com/api/partner/v2/orders \
  -H "Authorization: Bearer $CATCHBACK_KEY" \
  -H "Idempotency-Key: okx-ord-7f3a9c21" \
  -H "Content-Type: application/json" \
  -d '{
    "pack_type": "bronze",
    "category": "pokemon",
    "odds": "standard",
    "quantity": 1,
    "recipient": "0x8f3c...e21a",
    "refund_address": "0x8f3c...e21a",
    "partner_user_ref": "okx-uid-102938"
  }'
```

```bash Non-crypto model
curl -X POST https://catchbackcards.com/api/partner/v2/orders \
  -H "Authorization: Bearer $CATCHBACK_KEY" \
  -H "Idempotency-Key: acme-ord-7f3a91" \
  -H "Content-Type: application/json" \
  -d '{
    "pack_type": "bronze",
    "category": "pokemon",
    "odds": "standard",
    "quantity": 1,
    "customer": "user-1842"
  }'
```
