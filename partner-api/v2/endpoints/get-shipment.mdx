---
title: "Get a shipment"
api: "GET /api/partner/v2/shipments/{id}"
description: "One shipment: the burn details once paid, then carrier tracking."
---

Scope: `nft:orders`

Once the shipping payment settles, `status` becomes `ready` and each token's `burn` holds what the holder burns it with. After every burn is seen, `fulfilment` carries the delivery. Statuses: [Shipping](/partner-api/v2/shipping#statuses).

This response never includes the `payment` object: replay the create POST to get it. We never return the delivery address or the shipping label.

<ParamField path="id" type="string" required>
  A `shipment_id`, or any `quote_id` (a token in a multi-token shipment returns its whole shipment).
</ParamField>

## Response

<ResponseField name="shipment" type="object">
  <Expandable title="shipment">
    <ResponseField name="shipment_id" type="string">Multi-token shipments only.</ResponseField>
    <ResponseField name="status" type="string">`awaiting_payment`, `ready`, `expired`, `redeemed` or `partially_redeemed` (multi-token only).</ResponseField>
    <ResponseField name="shipping_cost" type="number" />
    <ResponseField name="holder" type="string">Every burn must come from this wallet.</ResponseField>
    <ResponseField name="expires_at" type="string">The end of the burn window: 24 hours from payment, shared by every token. A one-tap shipment: the end of its 30 minutes to sign.</ResponseField>
    <ResponseField name="paid_at" type="string | null" />
    <ResponseField name="payment_refund_due" type="boolean">`true` when a payment arrived but opened no burn: a one-token shipment paid more than 1% short, a token that already had another paid shipment, or a token burned another way first. CatchBack refunds it; nothing ships on it.</ResponseField>
    <ResponseField name="payment_method" type="string">One-token shipments only: `signature` (one tap, paid in its burn) or `checkout` (paid first).</ResponseField>
    <ResponseField name="tokens" type="object[]">
      Multi-token shipments only: `token_id`, `quote_id`, `status` (`awaiting_payment`, `ready`, `expired`, `redeemed` or `dropped`), `burned_at`, `burn_tx` and `burn`.
    </ResponseField>
    <ResponseField name="quote_id" type="string">One-token shipments only (with `burn` at the top level).</ResponseField>
    <ResponseField name="token_id" type="string">One-token shipments only: the token this shipment ships (decimal).</ResponseField>
    <ResponseField name="burn" type="object | null">
      What the holder burns with, while the token is `ready`. **EVM:** `{ "quote": { ...the Quote tuple, "kind": 2, "amount": "0" }, "signature": "0x..." }`: call `burnWithQuote` exactly as for a [sell-back](/partner-api/v2/sell-back#evm-burn-with-the-signed-quote). **Solana:** `{ "transaction": "<base64>", "vault": "...", "last_valid_block_height": ... }`: each GET builds a fresh transaction, so fetch it right before signing.
    </ResponseField>
    <ResponseField name="fulfilment" type="object | null">
      Null until every burn is seen. Then `status` (`pending`, `processing`, `shipped`, `delivered`, `cancelled` or `needs_review`), `carrier`, `service`, `tracking_number`, `tracking_url` (the carrier's own tracking page), `shipped_at`, `expected_delivery` (a `YYYY-MM-DD` date), `delivered_at` and `created_at`.
    </ResponseField>
  </Expandable>
</ResponseField>

## Errors

| Status | Code | When |
|---|---|---|
| `400` | `CRYPTO_WALLET_MODEL_ONLY` | Your program is on the Non-crypto model: it has no tokens or wallets. Use the [customer endpoints](/partner-api/v2/settlement) |
| `404` | `UNKNOWN_SHIPMENT` | No such shipment in your program |
