---
title: "Renew a shipment"
api: "POST /api/partner/v2/shipments/{id}/renew"
description: "A new 24-hour burn window for a paid shipment whose window lapsed, under the same quote ids."
---

Scope: `nft:orders`

If not every token was burned within the 24 hours, the shipment shows `status: "expired"`, with no `burn` on the tokens still unburned. Renewing gives the unburned tokens a new 24-hour window under the same `quote_id`s; the shipping already paid still counts. No body.

- A window that is still open is returned unchanged with `renewed: false`.
- **If a multi-token shipment's window lapses and it isn't renewed,** it closes **24 hours after `expires_at`**: the tokens already burned ship, and the rest are `dropped` (still live in the holder's wallet). The shipment's `status` becomes `partially_redeemed`.
- A one-token shipment renews the same way (`{id}` is its `quote_id`) and answers with that shipment's own shape; it never closes by itself.
- A burn window lapsing sends no webhook: watch `expires_at`.

<ParamField path="id" type="string" required>
  A `shipment_id`, or any `quote_id`.
</ParamField>

## Response

<ResponseField name="shipment" type="object">The shipment, in its [Get a shipment](/partner-api/v2/endpoints/get-shipment) shape, with fresh `burn`s and a new `expires_at`.</ResponseField>
<ResponseField name="renewed" type="boolean">`false` when the window was still open and nothing changed.</ResponseField>

## Errors

| Status | Code | When |
|---|---|---|
| `400` | `CRYPTO_WALLET_MODEL_ONLY` | Your program is on the Non-crypto model: it has no tokens or wallets. Use the [customer endpoints](/partner-api/v2/settlement) |
| `404` | `UNKNOWN_SHIPMENT` | No such shipment in your program |
| `409` | `NOT_PAID` | The shipping isn't paid yet. A one-tap shipment is paid in its burn: past its 30 minutes to sign, estimate and create it again |
| `409` | `ALREADY_REDEEMED` | The token was already burned; on a multi-token shipment, the box is shipping (every token burned, or the grace period closed it) |
| `409` | `TOKEN_NOT_LIVE` | A token was burned some other way (`token_ids` lists them on a multi-token shipment). Checked even while the window is still open |
| `409` | `TOKEN_BURNED` | The chain shows a token burned before our record caught up |
| `409` | `HOLDER_CHANGED` | A token still to be burned changed hands after the shipping was paid (`token_ids` lists them on a multi-token shipment). The shipment can't be renewed: contact CatchBack support with the `shipment_id` or `quote_id`. Tokens already burned still ship once the grace period ends |
| `503` | `CHAIN_UNAVAILABLE` | We couldn't read the token's owner from the chain; retry shortly |

```bash cURL

  -H "Authorization: Bearer $CATCHBACK_KEY"
```
</RequestExample>
