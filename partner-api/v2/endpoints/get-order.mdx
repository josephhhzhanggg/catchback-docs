---
title: "Get an order"
api: "GET /api/partner/v2/orders/{id}"
description: "One order, or a multi-pack order with its units, by our id or your Idempotency-Key."
---

Scope: `nft:orders`

Returns `{ "order": { ... } }`. After a lost response, this is how you find out how an order ended.

<ParamField path="id" type="string" required>
  The order's `id`, or the `Idempotency-Key` you sent. A multi-pack order's `id` or key returns the whole order with its `units`; one unit's `id` returns that unit.
</ParamField>

## Response

<ResponseField name="order" type="object">
  <Expandable title="order">
    <ResponseField name="order_id" type="string">Your `Idempotency-Key`.</ResponseField>
    <ResponseField name="id" type="string">Our id.</ResponseField>
    <ResponseField name="status" type="string">See [Orders and statuses](/partner-api/v2/orders#order-statuses). A multi-pack order adds `processing` and `completed`.</ResponseField>
    <ResponseField name="pack_type" type="string" />
    <ResponseField name="category" type="string" />
    <ResponseField name="odds" type="string">The odds the pack is opened at.</ResponseField>
    <ResponseField name="price" type="number">In dollars. On a multi-pack order, the total; `unit_price` is one pack.</ResponseField>
    <ResponseField name="recipient" type="string | null">Null on a [Paying through you](/partner-api/v2/settlement) program.</ResponseField>
    <ResponseField name="mint_chain" type="string | null">Null on a Paying through you program.</ResponseField>
    <ResponseField name="paid_at" type="string | null" />
    <ResponseField name="custody" type="string">`wallet` (the item mints as an NFT to `recipient`) or `vault` (Paying through you: the card stays in the `customer`'s CatchBack vault, and the order ends `in_vault` instead of `minted`). On a multi-pack order, on each unit.</ResponseField>
    <ResponseField name="customer" type="string">Only when `custody` is `vault`: the customer, by your own id.</ResponseField>
    <ResponseField name="pull" type="object | null">
      Set once the pack opens: `card_id`, `category`, `name`, `value` (the item's value when it was pulled; it anchors the [sell-back offer](/partner-api/v2/sell-back)) and `pulled_at`.
    </ResponseField>
    <ResponseField name="token" type="object | null">
      Always null when `custody` is `vault`. Set once the mint is reserved: `chain`, `contract` (on a Solana program, `collection` and `asset` instead), `token_id`, `status` and `tx`. `status` is `pending` (reserved, not sent), `submitted`, `confirmed`, `failed` (being retried), or `burned` once the token has been sold back or shipped.
    </ResponseField>
    <ResponseField name="failure_reason" type="string | null">Why an order is `mint_failed`, `expired`, `refund_due` or `refunded`; otherwise null.</ResponseField>
    <ResponseField name="created_at" type="string" />
    <ResponseField name="quantity" type="integer">Multi-pack orders only.</ResponseField>
    <ResponseField name="unit_price" type="number">Multi-pack orders only.</ResponseField>
    <ResponseField name="units" type="object[]">Multi-pack orders only: each unit in the single-order shape plus `batch_id` and `unit` (1 to `quantity`), with its own `pull` and `token`.</ResponseField>
    <ResponseField name="batch_id" type="string">On a unit only: the multi-pack order's `id`.</ResponseField>
    <ResponseField name="unit" type="integer">On a unit only: its number, 1 to `quantity`.</ResponseField>
  </Expandable>
</ResponseField>

This response never includes the `payment` object: replay [Create an order](/partner-api/v2/endpoints/create-order) with the same `Idempotency-Key` to get it back.

## Errors

| Status | Code | When |
|---|---|---|
| `404` | `UNKNOWN_ORDER` | No such order in your program (by id or `Idempotency-Key`) |

```bash cURL

  -H "Authorization: Bearer $CATCHBACK_KEY"
```
