In about 15 minutes you'll run the whole flow a customer goes through: buy a pack, receive the item, and sell it back. It all happens in the **sandbox**, a test copy of the API. Payments there are simulated, so no real money moves, but the digital representations are real tokens on a public test network.

There's one walkthrough per [integration model](/partner-api/v2/integration-models). Your sandbox runs the model you chose in Get started.

## Before you start

**Get your sandbox key.** Sign in to your manager at `catchback.com/<slug>/admin/api` and open **Get started**. An owner clicks **Set up my sandbox**, then creates a sandbox key there. Copy it when it's shown: it isn't shown again.

- The **sandbox base URL**, where the test API lives, is `https://sandbox.catchbackcards.com`.
- Your **test chain** is Base Sepolia (`evm:84532`). The **sandbox contract address** comes back as `contract` on every token and quote.

No manager access yet? Email [support@catchbackcards.com](mailto:support@catchbackcards.com) and we'll set you up.

**What you need.** A test wallet address on that chain, standing in for your customer. Any EVM wallet works (MetaMask, Rabby, or one your code creates). It needs no gas: selling back and shipping only ask the wallet to sign, and we send the burn ([Burn without gas](/partner-api/v2/endpoints/relay-burn)). Only a transfer between your own test wallets needs a little testnet ETH from a public faucet.

Save the two values you'll use in every call:

```bash
export CATCHBACK_BASE_URL="https://sandbox.catchbackcards.com"
export CATCHBACK_KEY="cb_test_…"          # your sandbox key: it works only at the sandbox base URL
export WALLET="0x…"                       # your test wallet address
```

## 1. Check your key

```bash
curl "$CATCHBACK_BASE_URL/api/partner/v2/keys" \
  -H "Authorization: Bearer $CATCHBACK_KEY"
```

You should see your key with `"scopes": ["nft:orders"]` and your `program`. A `401` means the key is wrong; a `403` means it's missing the `nft:orders` scope, so contact us.

## 2. Pick a pack

List the packs you can sell:

```bash
curl "$CATCHBACK_BASE_URL/api/partner/v2/catalog/packs?category=pokemon" \
  -H "Authorization: Bearer $CATCHBACK_KEY"
```

Each pack has a `pack_type` (for example `bronze`), a `price` in dollars, and `available`. Pick one where `available` is `true`: sandbox stock is thin, so a pack that sells in production may be out here. To see its odds and every item it can pull, the same view you'd show a customer, call [Get a pack's odds and pool](/partner-api/v2/endpoints/get-pack-pool) with that `pack_type`; for a pack that sells the odds choice, its `available` says whether those odds are selling.

Save the one you picked:

```bash
export PACK="…"                           # a pack_type with "available": true
```

## 3. Create an order for your test wallet

```bash
curl -X POST "$CATCHBACK_BASE_URL/api/partner/v2/orders" \
  -H "Authorization: Bearer $CATCHBACK_KEY" \
  -H "Idempotency-Key: quickstart-001" \
  -H "Content-Type: application/json" \
  -d "{ \"pack_type\": \"$PACK\", \"category\": \"pokemon\", \"recipient\": \"$WALLET\" }"
```

- `recipient` is the wallet the item is delivered to.
- `Idempotency-Key` is your own id for the order. If a call fails or times out, send it again with the same key and you'll get the same order back, never a second one. You'll also use it to look the order up.

The response has the `order`, with `"status": "awaiting_payment"`, and a `payment`. In production you'd hand `payment` to your customer to pay. Here, copy `payment.intent_id`: it starts with `sbx_pi_`.

## 4. Pay for it (simulated)

```bash
curl -X POST "$CATCHBACK_BASE_URL/api/partner/v2/sandbox/payments/sbx_pi_…" \
  -H "Authorization: Bearer $CATCHBACK_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

This marks the payment as settled, exactly as a real customer payment would. The pack opens as the payment settles, so the response usually says `"status": "rolled"` rather than `paid`, and `webhooks` counts the webhook deliveries the call made.

## 5. Open the pack and receive the item

Our background work runs every two minutes. In the sandbox you can also run it straight away by calling **tick**, so you don't have to wait:

```bash
curl -X POST "$CATCHBACK_BASE_URL/api/partner/v2/sandbox/tick" \
  -H "Authorization: Bearer $CATCHBACK_KEY"

curl "$CATCHBACK_BASE_URL/api/partner/v2/orders/quickstart-001" \
  -H "Authorization: Bearer $CATCHBACK_KEY"
```

Repeat both calls until `order.status` reaches `minted`. Along the way it moves:

| Status | What happened |
|---|---|
| `paid` | The payment settled |
| `rolled` | The pack opened. `order.pull` shows the item: its name and value |
| `minted` | The digital representation is in your test wallet. `order.token.token_id` is its id |

That's the moment your app shows the customer what they pulled. Check your test wallet: the token is there.

## 6. Sell it back

Ask for a quote. It fixes the price for 10 minutes:

```bash
curl -X POST "$CATCHBACK_BASE_URL/api/partner/v2/tokens/TOKEN_ID/quote" \
  -H "Authorization: Bearer $CATCHBACK_KEY" \
  -H "Content-Type: application/json" \
  -d "{ \"kind\": \"sellback\", \"holder\": \"$WALLET\" }"
```

`amount_usd` is what the customer gets. To accept, the **wallet holder** signs the `quote` (a signature, not a transaction, so no gas), and you send the signature to [`POST /tokens/{tokenId}/burn`](/partner-api/v2/endpoints/relay-burn): we send the burn and pay its gas. The signing code is on the [Sell-back](/partner-api/v2/sell-back#evm-without-gas) page, and the full run below does it end to end. (A holder with Base Sepolia ETH can instead send the burn itself: [Burn with the signed quote](/partner-api/v2/sell-back#evm-burn-with-the-signed-quote).)

```bash
curl -X POST "$CATCHBACK_BASE_URL/api/partner/v2/tokens/TOKEN_ID/burn" \
  -H "Authorization: Bearer $CATCHBACK_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "quote_id": "QUOTE_ID", "holder_signature": "0x…" }'
```

Then tick and check the quote:

```bash
curl -X POST "$CATCHBACK_BASE_URL/api/partner/v2/sandbox/tick" \
  -H "Authorization: Bearer $CATCHBACK_KEY"

curl "$CATCHBACK_BASE_URL/api/partner/v2/quotes/QUOTE_ID" \
  -H "Authorization: Bearer $CATCHBACK_KEY"
```

When `quote.payout.status` is `sent`, the sale is complete, and in the sandbox the payout lands instantly.

That's the whole flow. To try shipping instead, see [Shipping](/partner-api/v2/shipping): estimate, create and pay a shipment, burn, then mark it shipped with [`POST /sandbox/shipments/{id}`](/partner-api/v2/endpoints/sandbox-ship).

## Non-crypto model in the sandbox

No wallet and no payment: orders go on your sandbox statement, and a customer is your own id for them. Pick any test id, and a pack with `available: true` from [step 2](#2-pick-a-pack) as `PACK`.

```bash
export CUSTOMER="test-customer-1"
```

**1. Buy two packs** for that customer. They open at once, into the customer's vault:

```bash
curl -X POST "$CATCHBACK_BASE_URL/api/partner/v2/orders" \
  -H "Authorization: Bearer $CATCHBACK_KEY" -H "Idempotency-Key: order-$(date +%s)" -H "Content-Type: application/json" \
  -d "{\"pack_type\":\"$PACK\",\"category\":\"pokemon\",\"quantity\":2,\"customer\":\"$CUSTOMER\"}"
```

**2. Read their vault.** Each card has its `card.id` and what it sells back for right now:

```bash
curl "$CATCHBACK_BASE_URL/api/partner/v2/customers/$CUSTOMER/vault" -H "Authorization: Bearer $CATCHBACK_KEY"
```

**3. Sell one back.** The payout is credited to your statement:

```bash
curl -X POST "$CATCHBACK_BASE_URL/api/partner/v2/customers/$CUSTOMER/cards/CARD_ID/sellback" \
  -H "Authorization: Bearer $CATCHBACK_KEY" -H "Content-Type: application/json" -d '{}'
```

**4. Ship the other.** Estimate (the sandbox has one fixed rate, with no insurance: leave `cover_amount` out), then create the shipment with that rate and its `amount` as `max_cost`:

```bash
curl -X POST "$CATCHBACK_BASE_URL/api/partner/v2/customers/$CUSTOMER/shipments/estimate" \
  -H "Authorization: Bearer $CATCHBACK_KEY" -H "Content-Type: application/json" \
  -d '{"card_ids":["SECOND_CARD_ID"],"address":{"name":"Alice Tester","address1":"1 Market St","city":"San Francisco","state":"CA","zip":"94105","country":"US","phone":"4155550100"}}'

curl -X POST "$CATCHBACK_BASE_URL/api/partner/v2/customers/$CUSTOMER/shipments" \
  -H "Authorization: Bearer $CATCHBACK_KEY" -H "Idempotency-Key: ship-$(date +%s)" -H "Content-Type: application/json" \
  -d '{"card_ids":["SECOND_CARD_ID"],"address":{"name":"Alice Tester","address1":"1 Market St","city":"San Francisco","state":"CA","zip":"94105","country":"US","phone":"4155550100"},"rate":{"carrier":"USPS","token":"sbx_usps_priority"},"max_cost":9.85}'
```

**5. Play our shipping team**, then read the tracking:

```bash
curl -X POST "$CATCHBACK_BASE_URL/api/partner/v2/sandbox/shipments/SHIPMENT_ID" \
  -H "Authorization: Bearer $CATCHBACK_KEY" -H "Content-Type: application/json" -d '{"status":"shipped"}'
curl "$CATCHBACK_BASE_URL/api/partner/v2/customers/$CUSTOMER/shipments" -H "Authorization: Bearer $CATCHBACK_KEY"
```

**6. Read your statement:** the orders, the sell-back credit and the postage, by customer id.

```bash
curl "$CATCHBACK_BASE_URL/api/partner/v2/settlement" -H "Authorization: Bearer $CATCHBACK_KEY"
```

**Webhooks.** If you registered one, the events for these steps (`nft_order.updated`, `sellback.updated`, `nft_shipment.updated`) arrive within about two minutes, when our background work picks them up. To get them at once, call [`POST /sandbox/tick`](/partner-api/v2/endpoints/sandbox-tick) after a step; `POST /sandbox/shipments/{id}` sends its own straight away.

Get started in your manager runs these same steps for you and ticks each one off as it sees it. Full details: [Non-crypto model](/partner-api/v2/settlement).

## How the sandbox differs from production

| Production | Sandbox |
|---|---|
| Unifold Payment Intent, paid by the customer | Intent ids start `sbx_pi_`; mark one paid with [`POST /sandbox/payments/{intentId}`](/partner-api/v2/endpoints/sandbox-pay) |
| `publishable_key`, deposit addresses | Placeholders (`pk_sandbox`, fixed addresses) |
| Background work and webhooks every two minutes | Also every two minutes, or right away when you call [`POST /sandbox/tick`](/partner-api/v2/endpoints/sandbox-tick) |
| USDC payouts and refunds | Real transactions on Base Sepolia in **CatchBack Sandbox USDC** (`sbxUSDC`, 6 decimals, [`0x20f75eed30960c7420363eba937634be7c331141`](https://sepolia.basescan.org/token/0x20f75eed30960c7420363eba937634be7c331141)), a test token worth nothing: a `sent` payout's `tx_hash` opens on BaseScan. Solana payouts are simulated, with no `tx_hash`. Payouts, refunds and deposit addresses name the test networks, `evm:84532` (Base Sepolia) and `solana:devnet`; `evm:8453` and `solana:mainnet` are accepted there as those |
| Carrier rates | One fixed rate: USPS Priority Mail (sandbox), $9.85, with no insurance option. A `cover_amount` there is refused (`COVER_UNAVAILABLE` on create) |
| Your mint chain | A public testnet, real contract |
| Sanctions screening | The real OFAC list |
| Webhook URLs | Public `https://` URLs, as in production. To receive on your own machine, use a tunnel such as ngrok |
| Your statement (Non-crypto model) | A sandbox statement with its own limits ($10,000 credit, $500 per customer per UTC day); nothing is ever billed |

All three sandbox endpoints return **404** outside the sandbox.

| Endpoint | What it does |
|---|---|
| [`POST /sandbox/payments/{intentId}`](/partner-api/v2/endpoints/sandbox-pay) | Pays an order's or a shipment's sandbox intent, exactly as a settled payment would |
| [`POST /sandbox/tick`](/partner-api/v2/endpoints/sandbox-tick) | Runs one pass of the background work (open, mint, watch the chain, pay out, ship) and delivers the webhooks it produced |
| [`POST /sandbox/shipments/{id}`](/partner-api/v2/endpoints/sandbox-ship) | Plays our shipping team: marks a burned shipment (or, on the non-crypto model, a created one) `shipped`, then `delivered` |

## A full run (TypeScript + viem)

Order, pay, mint and sell back, with no gas at all: the sell-back is signed by the wallet and sent by us ([EVM without gas](/partner-api/v2/sell-back#evm-without-gas)). `alice` and her viem wallet are yours; `types` (the EIP-712 quote types) is on the [Sell-back](/partner-api/v2/sell-back#check-the-quote-before-the-customer-signs) page.

```ts
const BASE = process.env.CATCHBACK_BASE_URL!;
const KEY = process.env.CATCHBACK_KEY!;

async function api(method: string, path: string, body?: unknown, idem?: string) {
  const res = await fetch(`${BASE}/api/partner/v2${path}`, {
    method,
    headers: { Authorization: `Bearer ${KEY}`, 'Content-Type': 'application/json', ...(idem ? { 'Idempotency-Key': idem } : {}) },
    body: body === undefined ? undefined : JSON.stringify(body),
  });
  return { status: res.status, body: await res.json() };
}

/** Tick the sandbox until `check` returns something. */
async function settle<T>(check: () => Promise<T | null | undefined | false>, tries = 20): Promise<T> {
  for (let i = 0; i < tries; i++) {
    const v = await check();
    if (v) return v;
    await api('POST', '/sandbox/tick');
    await new Promise((r) => setTimeout(r, 1500));
  }
  throw new Error('did not settle');
}

// 1. Pick an available pack and read its odds.
const { body: cat } = await api('GET', '/catalog/packs?category=pokemon');
const pack = cat.packs.find((p: any) => p.available);
const { body: pool } = await api('GET', `/catalog/packs/pool?pack_type=${pack.pack_type}&category=pokemon`);

// 2. Order it for Alice, and pay (sandbox).
const key = `ord-${crypto.randomUUID()}`;
const { body: created } = await api('POST', '/orders', { pack_type: pack.pack_type, category: 'pokemon', recipient: alice.address }, key);
await api('POST', `/sandbox/payments/${created.payment.intent_id}`, {});

// 3. Tick until minted.
const order = await settle(async () => {
  const o = (await api('GET', `/orders/${key}`)).body.order;
  if (o.status === 'refund_due' || o.status === 'refunded') throw new Error(o.failure_reason);
  return o.status === 'minted' ? o : null;
});
const tokenId = order.token.token_id;

// 4. Alice sells it back without gas: quote, sign, we send the burn; tick until paid.
const { body: quote } = await api('POST', `/tokens/${tokenId}/quote`, { kind: 'sellback', holder: alice.address });
const q = quote.quote;
const holderSignature = await aliceWallet.signTypedData({
  account: aliceWallet.account!,
  domain: { name: 'CatchBackCards', version: '1', chainId: 84532, verifyingContract: quote.contract },
  types,
  primaryType: 'Quote',
  message: {
    tokenId: BigInt(q.tokenId), kind: Number(q.kind), quoteId: q.quoteId, holder: q.holder,
    payoutHash: q.payoutHash, amount: BigInt(q.amount), expiresAt: BigInt(q.expiresAt),
  },
});
await api('POST', `/tokens/${tokenId}/burn`, { quote_id: quote.quote_id, holder_signature: holderSignature });
await settle(async () => {
  const r = (await api('GET', `/quotes/${quote.quote_id}`)).body.quote;
  return r.payout.status === 'sent' ? r : null;
});
```

A trade between wallets (`transferFrom`) and a burn the holder sends itself (`burnWithQuote`) are transactions, so they need a little Base Sepolia ETH from a public faucet. The sandbox gives test wallets none, so the run above uses only signatures.

<Tip>
  Use a separate key per environment (sandbox, production).
</Tip>
