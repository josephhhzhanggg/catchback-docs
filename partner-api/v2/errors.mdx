title: "Errors"
description: "Status codes and every error code in Partner API v2."
---

Error bodies are `{ "error": "<message>" }`. Errors your integration should act on also carry a stable `code`, and some carry extra fields. **Branch on `code`, never on the message text.**

```json
{ "error": "Too many requests. Slow down.", "code": "RATE_LIMITED", "retry_after_seconds": 12 }
```

## Status codes

| Status | Meaning |
|---|---|
| `400` | Bad parameter or body |
| `401` | Missing, malformed, disabled, expired or unknown API key |
| `402` | Not enough money: your credit limit (`CREDIT_LIMIT`), or the holder's postage on a one-tap burn (`INSUFFICIENT_FUNDS`) |
| `403` | Scope, program, or a wallet or customer we can't serve |
| `404` | No such order, token, quote, shipment, payment, webhook, customer, card or pack in your program, or no such endpoint (`NOT_FOUND`) |
| `409` | The token, shipment, key, rate or price is not in the state the request needs |
| `422` | An `Idempotency-Key` reused for a different request |
| `429` | A request-rate limit (`RATE_LIMITED`), or a daily or unpaid-order limit; each carries `retry_after_seconds` |
| `500` | Our fault: retry with backoff, with the same `Idempotency-Key` where the endpoint takes one |
| `502` | The chain refused a burn (`CHAIN_REFUSED`); nothing was burned |
| `503` | A dependency (wallet screening, the chain, the proof, webhooks) is briefly unavailable; retry shortly |

The errors every endpoint can return before it does anything else (`401`, `403`, `429`, `503`) are listed on [Authentication and keys](/partner-api/v2/authentication#errors-every-endpoint-can-return-first).

## MCP server codes

The [MCP server](/partner-api/v2/mcp) returns these as a tool result with `isError: true`, never as an HTTP status. Every other code reaches the assistant unchanged from the endpoint the tool calls.

| `code` | When |
|---|---|
| `UNKNOWN_TOOL` | No tool by that name |
| `MISSING_SCOPE` | Your key lacks `nft:orders`; `next_step` says what to do. `whoami` reports the same in `access.code` |
| `MISSING_ARGUMENT` | A required argument (`token_id`, `customer`, `shipment_id`, ...) is missing, null or empty; `argument` names it |
| `UNKNOWN_ARGUMENT` | The tool doesn't take that argument; `argument` names it and the message lists what it takes |
| `BAD_ARGUMENT` | An argument has the wrong type (a string where a number goes, an object as an id); `argument` names it |
| `BAD_PATH` | `read_doc` was given something that isn't a docs page path from `search_docs` |
| `DOC_NOT_FOUND` | `read_doc` was given a path with no page; find it with `search_docs` |
| `DOCS_UNAVAILABLE` | The docs couldn't be reached; try again shortly |

## Errors without a code

A `400` without a `code` is a malformed request (a `kind` other than `sellback` on a quote, a `status` other than `shipped` or `delivered` on the sandbox shipment endpoint). Every unknown order, token, quote, shipment, payment or webhook id answers `404` with its `UNKNOWN_*` code, and a path no endpoint matches answers `404` with `NOT_FOUND`. A sandbox endpoint called in production answers `404` `Not found` with no code. A sell-back quote or burn on a program with no contract yet answers `409` without a code.

A `500` body says `Something went wrong. Retrying is safe: send the same Idempotency-Key if the request had one.` Retry with backoff.
