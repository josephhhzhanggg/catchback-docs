---
title: "MCP server"
description: "Give an AI agent the Partner API as tools."
---

If your integration is an AI agent, connect it to our [Model Context Protocol](https://modelcontextprotocol.io) server instead of writing HTTP calls. Every tool calls the same REST endpoint documented here, with your key, so scopes, idempotency and purchase limits apply exactly the same way.

- **URL:** `https://catchbackcards.com/api/mcp`
- **Transport:** Streamable HTTP, stateless, JSON responses
- **Auth:** the same `Authorization: Bearer cb_live_...` header

The agent only sees the tools your key has scopes for, plus `whoami`, which every key gets.

## Connect

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http catchback https://catchbackcards.com/api/mcp \
      --header "Authorization: Bearer cb_live_..."
    ```
  </Tab>
  <Tab title="JSON config">
    ```json
    {
      "mcpServers": {
        "catchback": {
          "type": "http",
          "url": "https://catchbackcards.com/api/mcp",
          "headers": { "Authorization": "Bearer cb_live_..." }
        }
      }
    }
    ```
  </Tab>
</Tabs>

`buy_packs`, `buy_card` and `create_shipment` take an `order_id` argument, which is sent as the `Idempotency-Key`. Have your agent generate one per order and reuse it when retrying that order. A retry of a purchase under a new `order_id` is a new order: a second set of packs, or a second card. `buy_card` also needs `max_price`, normally the `price` that `search_cards` returned, and `create_shipment` needs `max_cost`, normally the `amount` that `estimate_shipment` returned, or its `total` if you send `cover_amount`.

A tool whose endpoint has an id in its path takes that id as an argument: `card_id` for `get_card`, `get_price_history` and `get_card_activity`, `listing_id` for `update_listing_price`, `checkout_id` for `get_order`, and `shipment_id` for `get_shipment`. Every other argument is the endpoint's query parameter or body field of the same name.

`create_test_account` returns a login for a person to sign in with. It doesn't move your agent onto that account: your other tools keep acting on your key's account and its real balance. See [Testing](/partner-api/testing).

[Card catalog export](/partner-api/endpoints/card-catalog), [Purchase report](/partner-api/endpoints/purchase-report), [Public card metadata](/partner-api/endpoints/get-public-card), [Balance history](/partner-api/endpoints/get-balance-history), and [funding and withdrawals](/partner-api/funding) are REST only, with no MCP tool.

An error comes back as a tool result with `isError: true` and the HTTP status in the text, so the agent can read it and react.
