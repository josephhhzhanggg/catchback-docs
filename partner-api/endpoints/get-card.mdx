---
title: "Get a card"
api: "GET /api/partner/v1/cards/{id}"
description: "Any card by its id, from any catalog, as the same card object every endpoint returns."
---

Scope: `read:catalog` · MCP tool: `get_card`

Looks one card up by id, wherever it is now: in the shop, in a pack's pool, in someone's vault, listed or shipped. You get the [card object](/partner-api/card-object) only, with nothing about who holds the card, how they got it, or whether it's for sale. To find cards you can buy, use [Search cards](/partner-api/endpoints/search-cards).

To show a card's metadata and images with no key and no prices, use [Public card metadata](/partner-api/endpoints/get-public-card).

<ParamField path="id" type="string" required>
  A card id: `item.id` or `card_id` from any other endpoint.
</ParamField>
<ParamField query="category" type="string">
  The card's catalog, if you know it (`item.category`): `pokemon`, `onepiece`, `sports`, `riftbound`, `watches`, `goods` (luxury goods) or `singles` (raw singles). Without it, every catalog is searched.
</ParamField>

A lookup is cached for up to a minute, a miss included, so a card added in the last minute can read as a `404` until then.

## Response

<ResponseField name="card" type="object">A [card object](/partner-api/card-object).</ResponseField>

## Errors

| Status | When |
|---|---|
| `400` | An id with a character other than letters, digits, `_` and `-`, or longer than 128 characters; or an unknown `category` (the seven above) |
| `404` | No card has this id (in that catalog, if you sent `category`) |
| `500` | We couldn't look the card up. Retry with backoff |

<RequestExample>
```bash cURL
curl "https://catchbackcards.com/api/partner/v1/cards/0e94dc61-5a2f-4b1e-9c3d-7f8a1b2c3d4e?category=pokemon" \
  -H "Authorization: Bearer $CATCHBACK_KEY"
```
</RequestExample>
