title: "Changelog"
description: "What changed in the Partner API, newest first."
---

Changes to `v1` are additive: a response can gain fields, an enum can gain values, and a new endpoint can appear, so build your parser to ignore what it doesn't know. A breaking change would ship under a new version prefix. Dates are US Pacific time.

<Update label="November 1, 2026" description="Test accounts, public card metadata, shipments, webhooks, orders held for review">
  - New: [Create a test account](/partner-api/endpoints/create-test-account) (`POST /test-accounts`, MCP tool `create_test_account`) and [List test accounts](/partner-api/endpoints/list-test-accounts) (`GET /test-accounts`, MCP tool `list_test_accounts`), scope `create:test_accounts`, granted on request: test logins with a $10,000 test balance. A test account is a login, not a key, and it can't use the marketplace, gifts, drops, battles, shipping, chat, DMs or withdrawals. New guide: [Testing](/partner-api/testing).
  - New: [Public card metadata](/partner-api/endpoints/get-public-card) (`GET /api/public/v1/cards/{id}`): a card's metadata and image URLs with no key and no prices, cached for 5 minutes at the CDN.
  - New: [Estimate a shipment](/partner-api/endpoints/estimate-shipment) (`POST /shipments/estimate`, MCP tool `estimate_shipment`), [Create a shipment](/partner-api/endpoints/create-shipment) (`POST /shipments`, MCP tool `create_shipment`), [List shipments](/partner-api/endpoints/list-shipments) (`GET /shipments`, MCP tool `list_shipments`) and [Get a shipment](/partner-api/endpoints/get-shipment) (`GET /shipments/{id}`, MCP tool `get_shipment`), scope `ship:cards`, granted on request: ship cards you hold to your customers at the carrier's full rate. New guide: [Shipping cards](/partner-api/shipping).
  - New: [Webhooks](/partner-api/webhooks), which we set up for you: a signed `POST` with retries for [`order.completed`, `listing.sold` and `shipment.updated`](/partner-api/webhook-events).
  - New: [Where you can call from](/partner-api/errors-and-limits#where-you-can-call-from). A key doesn't get around our sanctions list, and a valid key now gets past any other limit on where partner endpoints and the MCP server can be called from.
  - [Rate limits](/partner-api/rate-limits#shared-limit-per-ip) now says that everything under `/api/` has a shared limit of 300 requests a minute per IP address, on top of the per-key limits.
  - [Buy packs](/partner-api/endpoints/buy-packs) and [Buy a card](/partner-api/endpoints/buy-card): when we can't confirm whether a purchase was charged, the answer is now `500 PAYMENT_OUTCOME_UNKNOWN` with `needs_review: true` and the order's `checkout_id`, not a `503`. Nothing is delivered and the order is held for us to settle: stop retrying, never place it again under a new order id, and follow it with [Get an order](/partner-api/endpoints/get-order).
  - A resend with the same order id answers `409 IDEMPOTENCY_IN_PROGRESS` with `needs_review: true` until we settle the order, and nothing is charged twice. Once we settle it, [Get an order](/partner-api/endpoints/get-order) answers `404` and the id is free to send again. See [Purchases that need review](/partner-api/idempotency#purchases-that-need-review).
  - A `503` on a purchase now only means the order certainly didn't go through, so retrying it with the same order id is safe.
</Update>

<Update label="October 29, 2026" description="Pull proofs, one-step price changes, partner accounts">
  - [Buy packs](/partner-api/endpoints/buy-packs): every pull carries a `proof`, its provably fair record, with a `verify_path` you can `GET` without a key to replay the draw. New guide: [Verify a pull](/partner-api/verify-a-pull).
  - [Change a listing's price](/partner-api/endpoints/update-listing-price) writes the new price in one step, so it lands whole or not at all. A buy or delist that lands first makes it a `409 LISTING_NOT_ACTIVE`, another price change a `409 LISTING_CHANGED`, and neither writes anything.
  - A partner account stays off CatchBack's VIP and Top Gifters leaderboards and recent-pull feeds, its pulls aren't posted as big-pull cards in chat, and it earns no CatchPoints or quest progress.
</Update>

<Update label="October 28, 2026" description="Card lookups, your listings, price changes, order history">
  - New: [Get a card](/partner-api/endpoints/get-card) (`GET /cards/{id}`, MCP tool `get_card`) and [Find a card by cert](/partner-api/endpoints/find-card-by-cert) (`GET /cards?cert=`, MCP tool `find_card_by_cert`), scope `read:catalog`: any card by its id or by the cert on its slab.
  - New: [Price history](/partner-api/endpoints/get-price-history) (`GET /cards/{id}/price-history`, MCP tool `get_price_history`): a card's CardLadder value readings, up to a year back.
  - New: [Card activity](/partner-api/endpoints/get-card-activity) (`GET /cards/{id}/activity`, MCP tool `get_card_activity`): a card's recent sales and listings, with nobody named.
  - New: [Your listings](/partner-api/endpoints/get-listings) (`GET /listings`, scope `read:account`, MCP tool `get_listings`): your own active listings, with your payout on each.
  - New: [Change a listing's price](/partner-api/endpoints/update-listing-price) (`PATCH /listings/{listing_id}`, scope `write:listings`, MCP tool `update_listing_price`): reprice a fixed-price listing in place, without delisting it.
  - New: [List orders](/partner-api/endpoints/list-orders) (`GET /orders`, MCP tool `list_orders`) and [Get an order](/partner-api/endpoints/get-order) (`GET /orders/{checkout_id}`, MCP tool `get_order`), scope `read:account`: your order history, paged by cursor, and one order by its id, even while it is still running.
  - [Search cards](/partner-api/endpoints/search-cards) applies its filters to every listing it reads, up to 5,000 rows from each source, and gains `truncated`. `has_more` is `false` on the last page and on page 20.
  - [Get vault](/partner-api/endpoints/get-vault): a listed card carries its `listing_id` and `listing_price`.
  - [List a card](/partner-api/endpoints/list-card) runs the app's seller checks, so the account needs a verified phone number.
</Update>

<Update label="October 26, 2026" description="Sealed pack pools">
  - [Get a pack's pool](/partner-api/endpoints/get-pack-pool) covers sealed packs (the Starter and the sealed mystery packs). The response gains `kind` (`slab` or `sealed`); a sealed pack lists its products in `products`, with `total_products`, and one band per product.
  - A sold-out pack with no pool to show returns `200` with `available: false` and an empty pool, instead of an error.
  - The Starter pack opens at the `standard` risk level only, and [List packs](/partner-api/endpoints/list-packs) says so in its `risk_levels`.
</Update>

<Update label="October 18, 2026" description="Vault acquisitions">
  - [Get vault](/partner-api/endpoints/get-vault) finds each card's latest acquisition across every kind of pack pull and buy, so its `pull_id` or `purchase_id` always names the acquisition a sell-back pays on.
</Update>

<Update label="October 14, 2026" description="Who am I, card limits">
  - New: [Who am I](/partner-api/endpoints/get-me) (`GET /me`, MCP tool `whoami`) works with any valid key and shows which account it acts as.
  - [Get account](/partner-api/endpoints/get-account) gains `card_limits`: your card and spend usage against the daily card caps.
</Update>

<Update label="October 12, 2026" description="Buying cards">
  - New: [Search cards](/partner-api/endpoints/search-cards) (`GET /marketplace/listings`, MCP tool `search_cards`) finds every card you can buy, from the shop and fixed-price user listings.
  - New: [Buy a card](/partner-api/endpoints/buy-card) (`POST /cards/purchase`, scope `buy:cards`, MCP tool `buy_card`), with a `max_price` guard and daily card and spend caps.
  - [Sell back cards](/partner-api/endpoints/sell-back) takes a `purchase_id` for a card you bought, and [Get vault](/partner-api/endpoints/get-vault) returns `purchase_id` and `purchased_at`.
  - Card orders share your account's order ids with pack orders, and an interrupted card order is closed the same way as a pack order.
</Update>

<Update label="October 11, 2026" description="Interrupted orders">
  - A pack order cut off after it was charged is now closed from our records, usually within about 10 minutes. Resending its order id then returns a shorter body marked `"reconciled": true`. See [Idempotency](/partner-api/idempotency#timeouts-and-interrupted-orders).
  - New error code: `409 IDEMPOTENCY_RETRY`, when an earlier attempt with the same order id failed just as the retry arrived. Resend it.
</Update>

<Update label="October 6, 2026" description="Pack pools and the full card object">
  - New: [Get a pack's pool](/partner-api/endpoints/get-pack-pool) (`GET /catalog/packs/pool`, MCP tool `get_pack_pool`): a pack's value bands, their odds at a risk level, and every card a pull can produce.
  - Every endpoint that returns a card returns the same [card object](/partner-api/card-object), with front, back and render images and the slab, set and value fields.
</Update>

<Update label="September 29, 2026" description="Buying packs and managing cards">
  - New: [Buy packs](/partner-api/endpoints/buy-packs) (`POST /packs/purchase`, scope `rip:packs`), with a required `Idempotency-Key`, one purchase per minute and 100 packs per day per key.
  - New: [Sell back cards](/partner-api/endpoints/sell-back) (`sell:cards`), [List a card](/partner-api/endpoints/list-card) and [Delist a card](/partner-api/endpoints/delist-card) (`write:listings`), [Get account](/partner-api/endpoints/get-account) and [Get vault](/partner-api/endpoints/get-vault) (`read:account`).
  - New: the [MCP server](/partner-api/mcp) at `/api/mcp`, with the same key.
  - [List packs](/partner-api/endpoints/list-packs) returns exactly the packs your account can buy, at the price it will be charged.
</Update>

<Update label="August 7, 2026" description="Purchase report">
  - New: [Purchase report](/partner-api/endpoints/purchase-report) (`GET /pulls`, scope `read:pulls`, opt-in): completed pack purchases in a time window, for revenue-share reporting.
</Update>

<Update label="August 4, 2026" description="Partner API v1">
  - Scoped API keys, and the first read-only endpoints: [List packs](/partner-api/endpoints/list-packs) and the [Card catalog export](/partner-api/endpoints/card-catalog) (scope `read:catalog`).
</Update>
